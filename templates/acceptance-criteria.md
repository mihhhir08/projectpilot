# Acceptance Criteria

Replace bracketed text with observable, project-specific behavior.

## Behavior

- [ ] Given `[starting state]`, when `[user action]`, then `[visible outcome]` occurs.
- [ ] The primary workflow completes without undocumented manual steps.
- [ ] Invalid input produces a clear error and recovery action.
- [ ] Empty and loading states explain what is happening and what to do next.

## Quality

- [ ] Mobile, desktop, or terminal output remains readable on supported surfaces.
- [ ] Accessibility requirements relevant to the interface are verified.
- [ ] Existing public APIs, commands, and stored data remain compatible unless the change documents otherwise.

## Verification

- [ ] Relevant tests, build, lint, and type checks pass.
- [ ] README or usage documentation matches the delivered behavior.
- [ ] The diff contains no unrelated files, secrets, credentials, or local artifacts.
